# Security Policy

## Supported Content

This repository contains educational and portfolio projects. Security fixes are
accepted for active project folders and documentation.

## Reporting a Vulnerability

Please do not disclose vulnerabilities publicly before triage.

Report security issues with:
- Project path and affected files
- Vulnerability description and impact
- Reproduction steps or proof of concept
- Suggested remediation (if available)

Use the contact details in SUPPORT.md and include "[SECURITY]" in the subject.

## Response Expectations

- Initial acknowledgment: within 3 business days
- Triage decision: within 7 business days
- Fix timeline: depends on severity and project complexity

## Severity Guidance

High severity examples:
- Authentication bypass
- Privilege escalation
- Sensitive data exposure
- Injection vulnerabilities with realistic exploit paths

Medium severity examples:
- Weak authorization checks
- Insecure default configuration
- Insufficient input validation

Low severity examples:
- Minor information disclosure without sensitive impact
- Non-exploitable misconfigurations

## Disclosure Process

1. Report received and acknowledged.
2. Reproduction and impact validated.
3. Fix plan and patch prepared.
4. Patch merged and deployed where applicable.
5. Public note added after remediation.
