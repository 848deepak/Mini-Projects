# Contributing Guide

Thank you for helping improve this repository.

## Contribution Scope

You can contribute by:
- Adding or improving project implementations
- Fixing bugs and documentation gaps
- Improving setup, tests, and developer experience
- Refining architecture, security, and performance

## Before You Start

1. Read the root README for structure and standards.
2. Choose a single project folder and keep changes scoped.
3. Confirm that your change matches the project objective.

## Branch and Commit Workflow

1. Create a feature branch from main.
2. Use clear commit messages with action and scope.
3. Keep commits small, focused, and reviewable.
4. Open a pull request with context and test evidence.

## Pull Request Checklist

- [ ] Changes are limited to intended scope
- [ ] README updates are included where behavior changed
- [ ] Setup/run steps are validated
- [ ] Relevant tests are added or updated
- [ ] No unrelated files are modified

## Coding Expectations

- Follow existing style in each project.
- Keep naming and folder conventions consistent.
- Prefer readable, maintainable solutions over clever shortcuts.
- Add concise comments only when logic is non-obvious.

## Documentation Expectations

Every non-trivial change should include:
- What changed
- Why it changed
- How to run or verify it
- Known limitations or follow-up items

## Reporting Bugs

When filing an issue, include:
- Project path
- Environment details
- Reproduction steps
- Expected vs actual behavior
- Logs, traces, or screenshots if relevant
